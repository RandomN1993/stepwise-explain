# 信号、节奏与异常处理

本文件是 SKILL.md"反馈 → 动作"表的完整版。判断顺序固定：先看是不是终止或跑题，再看节奏，最后才决定推进。

## 1. 完整信号表

| 类别 | 用户的话 | 动作 | 不要做什么 |
| --- | --- | --- | --- |
| 明确推进 | 继续、懂了、下一个、开始、go、嗯嗯（重复两次以上） | 用最短形式讲下一节 | 不要把"懂了"理解成要重新总结 |
| 含糊 | 嗯、哦、然后呢、好的、行、还行 | 一句话复述本节结论，问"这样理解对吗"，确认后推进 | 不要默认推进，也不要重讲整节 |
| 没懂 | 没懂、懵、不太明白、换个例子、为什么、展开说说 | 同一节换讲法，走第 2 节的阶梯 | 不要跳到下一节，不要只说"再说一遍" |
| 节奏 | 太简单、跳过、快点、直接说结论、详细点 | 压缩或加深：压缩见第 3 节；加深则本节换更细的拆法 | 不要改骨架来实现"讲细点" |
| 跑题 | 顺便问一下……、另外……、先不说这个…… | 一句话回答，编号进暂停区，回到当前节 | 不要顺着跑题重新组织整段讲解 |
| 改结构 | 拆一下、合并第 2、3 节、先讲第 4 节、加一节 | 出骨架修订块（见第 4 节） | 不要嘴上答应、正文还按旧结构写 |
| 终止 | 先到这、我要走了、够了、下次再说 | 输出存档块，结束 | 不要把没讲完的内容硬塞进收尾 |
| 拒绝分节 | 别分了、直接全部给我 | 降级：一次给全，但按节组织并保留节间回收句 | 不要继续一节一节挤 |

判断不了时，问一句"你是想继续，还是这节还没通？"——只问这一句，不要附带讲解。

## 2. 四级换讲法阶梯

同一节没听懂时按顺序降级，不要跳级，也不要重复同一讲法。

| 级 | 做法 | 适用 | 篇幅 |
| --- | --- | --- | --- |
| 1 换例子 | 换一个用户生活里更熟悉的场景，结构不变 | "看不懂这个抽象说法" | 3–6 行 |
| 2 换类比 | 用一个有对应关系的具体物（投票、筛子、队列）映射机制 | "知道定义但不知道它在干嘛" | 4–8 行 |
| 3 退回接口 | 回到上一节的结论，指出本节只是在它上面加了一步 | "不知道这节从哪冒出来的" | 2–3 行 + 一句衔接 |
| 4 最小反例 | 给出一个不满足本节结论的具体例子，让差异自己显形 | "觉得这结论理所当然/没必要" | 3–6 行 |

规则：

- 每次只换一级，换完仍给一个检查点；不要连换三级再停。
- 同一节最多换三次。第三次仍没懂，说明节太大或骨架不对：提议"拆成 k a / k b"或"退回第 k−1 节重讲一句"，由用户选。
- 换讲法时保留节标题与进度条，标题后标「· 再讲一次」，并写明"这次换的是：第 n 级"；定位块三行照旧，否则用户会以为进了新节。
- 换讲法时保留本节结论不变，只换抵达路径。若发现结论本身错了，走骨架修订，不叫"换个讲法"。
- 用户说"懂了"后不要把换过的讲法再复述一遍。

## 3. 压缩与合并

用户嫌慢或内容已被提前答出时，三种压缩方式，选一种并说明：

1. **降密度**：后续节只给"结论 + 一句依据"，去掉机制与例子；算法类至少保留 3 步最小实例，除非用户明说跳过例子。
2. **并节**：把功能上同属一类的剩余节合成一节，用编号小标题分隔。合并后仍只占一个回合，但仍要给定位块——定位块里的"到哪去"改成"讲完即收束"。
3. **直达收束**：跳过剩余节直接给收束页，把未讲节的结论压进回填表，并明说"这几节没展开，需要时再回来"。

压缩的反向操作是"加深"：用户说"详细点"时，不增加新节，而是把当前节按"结论 → 机制 → 例子 → 边界"写全。仍超篇幅时先判断是不是混进了两个功能单元：是就按功能拆节，不是就允许写长——复杂主题本来就不设固定上限。

## 4. 骨架修订

触发条件（任一成立即修订，不要硬撑旧骨架）：

- 用户要求改分节、调顺序、合并或加节。
- 本节写到一半发现实际内容量远超预估（超过 2 倍预算）。
- 检查点暴露出用户卡在更早的前提上。
- 用户跑题的问题其实是主干的一部分。

修订块固定四行：旧 → 新、原因、影响、下一步指令。影响必须落到下面三档之一：

| 档位 | 判据 | 动作 |
| --- | --- | --- |
| 无影响 | 只增删后面的节，已讲结论仍成立 | 说明后直接继续 |
| 需回补 | 已讲结论仍对，但新结构需要一句衔接 | 补一句差异，再继续 |
| 需重讲 | 已讲整节的前提被推翻 | 明说"第 k 节要重讲"，并说明重讲范围 |

修订后不要立刻连讲两节，仍然一次一节。修订只做一次，同一段讲解里反复改骨架说明第一次就没想清。

## 5. 两个缓冲区：跑题问题 P 与延后细节 D

跑题问题不丢、也不当场展开。规则：

- 编号 P1、P2……，记"问题 + 一句话答案"。
- 回到主线时只说一句"P1 记下了，先回到第 k 节"，不重复答案。
- 全部讲完后，在收束页末尾问"暂停区还有 P1、P2，要现在回答吗"，或按用户要求并入。
- 暂停区问题若其实是主干，走骨架修订把它升格成节，而不是留在暂停区。

细节同理，另开 D 清单（第一遍故意不讲的加速、采样、实现与调参）：

- 在骨架页先列 2–4 条，编号 D1、D2……，让用户知道"不是漏了，是暂时不讲"。
- 讲到某节时只补一句"这条细节记在 D2"，随即回到主线；不因为它顺手就展开。
- 用户点名某条 D，才算授权：能一句话说清就在节内补，说不清就单独开一节，并在骨架修订块里登记。
- 收束页把 D 与 P 并列问一次，不默认展开。

## 6. 存档与续讲

默认不落盘。用户说"先到这""下次接着讲""存一下"时：

1. 先在对话里输出存档块（格式见 [shell-templates.md](shell-templates.md) 第 6 节）。
2. 用户同意后再写文件，默认文件名 `stepwise-<主题>.md`，放当前工作目录或用户指定位置。
3. 下次续讲时先读存档，出"续讲定位块"，从下一节开始；不要重新出整张路线图，也不要重讲已讲节。

存档内容五项：总问题、已讲节与各节一句结论、未讲节、暂停区、用户已明确掌握的内容。

## 7. 收束后的改进方向与另开会话

讲算法、协议、系统设计时，收束页给"改进方向"：可行 2–4 条、不可行 2–3 条，每条一行。规则：

1. 只写方向与代价，不写实施步骤；不可行的必须写清破坏哪个假设、触发哪种攻击、代价涨多少。
2. 拿不准的标「待验证」，给出验证的第一步。
3. **必须等用户选中**，才把某条建议升级为下一轮讲解；不选中就停在列表，不自行展开。
4. 选中后生成"背景卡"（见 [shell-templates.md](shell-templates.md) 第 10 节），供用户复制到新会话——新会话没有历史，卡里要带足算法与参数、已确认结论、约束、要回答的问题、建议起点。
5. 新会话第一回合仍按本技能出骨架页；不要在新会话里重新讲一遍已经讲过的内容，除非用户要求。

平台限制：DeepSeek Harness 里会话由用户新建，助手不能直接开；本技能只产出清单与背景卡。

## 8. 常见失败对照

| 失败 | 表现 | 修正 |
| --- | --- | --- |
| 一口气倒完 | 骨架页后面直接跟了全部正文 | 骨架页只发表格与确认句，写完就停 |
| 每节重贴路线图 | 每节开头把整张表再贴一遍，正文被挤短 | 只留位置示意 + 进度条 + 三行定位 |
| 检查点变考试 | 节末连问三四个问题 | 只留一个，问最可能的误读 |
| "嗯"被当成懂了 | 用户只回了"嗯"，下一节已经开场 | 先复述结论确认，再推进 |
| 跑题后重讲 | 回答跑题问题时把本节又讲了一遍 | 一句话答 + 编号 + 回主线 |
| 按形式切节 | 每节字数凑齐、都分三块，功能却混着 | 按功能拆：两个独立问题就拆两节 |
| 例子当第二节课 | 实例里引入新术语，比正文还长 | 实例只验证本节结论，3–7 步 |
| 细节前置 | 第一遍就把加速、采样、调参讲透 | 默认进 D 清单，用户点名再展开 |
| 两段式对比 | 先讲 A 再讲 B，读者自己找差异 | 改并排表：维度做行、对象做列，标「▲」 |
| 建议越权展开 | 收束页给完建议就自动讲第一条 | 等用户选中再展开，否则只列清单 |
| 骨架死撑 | 用户已卡在前提上，仍按原顺序讲 | 出修订块，落到"需重讲"档 |
| 收尾丢线 | 最后一节讲完直接结束，没有回填表 | 必须给收束页，把结论连成一条线 |

# 完整示例：为什么要除以 $\sqrt{d_k}$

选这个主题是因为它的四节有真实的先后依赖，第 2、3 节也最容易卡住，正好演示"换讲法 → 拆节 → 回收"。下面的助手回复按真实输出格式给出，`>` 开头是给读技能的人看的说明，不发给用户。

## 回合 1：骨架页

````markdown
## 总体路线

一句话：这次要弄懂 scaled dot-product attention 里为什么要把分数除以 $\sqrt{d_k}$。

**依赖**：1 加权求和 → 2 分数变大 → 3 softmax 饱和 → 4 缩放收口

| # | 本节 | 你会得到的结论 | 为什么排在这 |
| --- | --- | --- | --- |
| 1 | 注意力就是加权求和 | 输出是 value 的加权平均，权重来自 query 与 key 的相似度 | 先分清被缩放的是分数，不是 value |
| 2 | 分数的量级随维度变大 | $q\cdot k$ 的标准差是 $\sqrt{d_k}$，维度越高分数越大 | 承接第 1 节，解释"为什么需要缩放" |
| 3 | softmax 在大分数下饱和 | 分数过大会让权重接近 one-hot，梯度变小 | 承接第 2 节，说明不缩放的代价 |
| 4 | 除以 $\sqrt{d_k}$ 把方差拉回 1 | 缩放后分数与维度无关，softmax 不饱和 | 收口，并解释为什么不是除以 $d_k$ |

共 4 节，不预估字数；第 k 节依赖第 k−1 节。

先不展开：多头注意力的并行实现、KV cache 与推理加速、不同注意力变体的采样策略。

要改分节、合并或跳过，现在说；没问题回「开始」。
````

> 只有表格与确认句，没有任何一节正文。这是整个技能里最容易被违反的一条。

## 回合 2：用户回「开始」，讲第 1 节

````markdown
### 第 1 / 4 节 · 注意力就是加权求和

`██░░░░ 1/4`　`[1] → 2 → 3 → 4`

- 从哪来：这是起点，回答"被缩放的是什么"。
- 为什么现在：先看清缩放作用在分数上，第 2 节才谈得上"分数为什么该缩放"。
- 到哪去：本节给出的分数 $s_i = q \cdot k_i$ 是第 2 节的分析对象。

本节目标：读完能说出注意力输出为什么是 value 的加权平均。

**结论**：注意力做的是加权平均，权重由 query 与 key 的相似度决定。

给定一个 query $q$，以及一组 key $k_i$ 和 value $v_i$：

$$
s_i = q \cdot k_i, \qquad a_i = \operatorname{softmax}(s)_i, \qquad \text{输出} = \sum_i a_i v_i .
$$

$s_i$ 是相似度分数，$a_i$ 是归一化后的权重。这里只有一步"额外操作"：softmax 之前，分数先除以 $\sqrt{d_k}$。本主题就是解释这一步。

一句话回收：后面所有讨论的对象都是 $s_i$，所以第 2 节问"$s_i$ 通常有多大"。

**停一下**：为什么权重必须归一化，也就是为什么要有 $\sum_i a_i = 1$？
继续回「继续」；没懂就回「没懂 + 卡在哪」，我换一种讲法。
````

## 回合 3：用户回「有点懵」，同节换讲法

用户：`有点懵，为什么要归一化还是没感觉。`

````markdown
结论不变：不归一化也能算，但输出会随候选数量缩放，"平均"就失去了含义。

换个例子。三个评委给同一部电影打 90、85、80，想得到 0–100 的总评，就取平均；再来十个评委，仍然取平均，得除以人数。softmax 干的是"除以人数"这件事，只是按分数指数比例分配，而不是均分。

所以归一化在这里有两个作用：让输出落在 value 的凸组合里、不会越加越大；让权重之间可以比较。

**停一下**：如果去掉 softmax，直接把 $s_i$ 当权重，输出会随序列长度怎么变？
懂了回「继续」；还卡着就回「卡在投票这个例子上」。
````

> 用户没说卡在哪，所以先复述结论，再用第 1 级（换例子）换讲法；仍以一个检查点收尾，没有擅自推进到第 2 节。

## 回合 4：用户回「懂了，继续」

````markdown
### 第 2 / 4 节 · 分数的量级随维度变大

`████░░ 2/4`　`1 → [2] → 3 → 4`

- 从哪来：第 1 节把分数写成 $s_i = q \cdot k_i$。
- 为什么现在：不先知道 $s_i$ 会随维度变大，就理解不了第 3 节的饱和问题。
- 到哪去：本节的 $\sqrt{d_k}$ 是第 4 节缩放系数的来源。

本节目标：读完能说出为什么维度变大时分数会跟着变大。

**结论**：$q \cdot k_i$ 是 $d_k$ 个乘积之和，各分量独立时，它的标准差是 $\sqrt{d_k}$。

设 $q, k \in \mathbb{R}^{d_k}$，各分量独立、均值为 0、方差为 1：

$$
q \cdot k = \sum_{j=1}^{d_k} q_j k_j, \qquad \operatorname{Var}(q \cdot k) = \sum_{j=1}^{d_k} \operatorname{Var}(q_j k_j) = d_k .
$$

方差是 $d_k$，标准差就是 $\sqrt{d_k}$。维度翻四倍，分数波动翻两倍——分数被"撑大"了。

一句话回收：分数天然带 $\sqrt{d_k}$ 的尺度，第 3 节看这个尺度对 softmax 做了什么。

**停一下**：如果 $d_k = 64$，分数大致在什么范围里波动？
继续回「继续」；没懂就回「没懂 + 卡在哪」。
````

## 回合 6–7：第 3 节卡住，拆节

用户：`继续。` → 助手讲第 3 节；用户：`这节有点长，而且我还是没懂为什么梯度会变小。`

````markdown
**骨架修订**
- 旧：1 加权求和 → 2 分数变大 → 3 softmax 饱和 → 4 除以 $\sqrt{d_k}$
- 新：1 加权求和 → 2 分数变大 → 3a 饱和现象 → 3b 梯度为什么变小 → 4 除以 $\sqrt{d_k}$
- 原因：第 3 节把"现象"和"梯度"混在一起，实际量超过预估的两倍。
- 影响：需重讲——第 3 节拆成 3a、3b，后面节号不变；前两节结论仍然成立，不用回补。

先讲 3a。
````

````markdown
### 第 3a / 4 节 · softmax 在大分数下饱和

`██████░░ 3a/4`　`1 → 2 → [3a] → 3b → 4`

- 从哪来：第 2 节得到分数标准差是 $\sqrt{d_k}$。
- 为什么现在：先看见饱和这个现象，3b 才谈得上它的后果。
- 到哪去：3b 会解释饱和为什么让梯度变小。

本节目标：读完能说出分数变大时 softmax 输出会变成什么样。

**结论**：分数越大，softmax 输出越尖，最后接近 one-hot。

以三个分数为例，softmax 前后对比：

| 分数 | softmax 后 |
| --- | --- |
| $(1, 2, 3)$ | $(0.09,\ 0.24,\ 0.67)$ |
| $(10, 20, 30)$ | $(\approx 0,\ \approx 0,\ \approx 1)$ |

第二行里，最大项几乎拿走了全部权重。这就是"饱和"：分布被压成了非 0 即 1。

一句话回收：输出越接近 one-hot，3b 要讲的梯度就越小。

**停一下**：维度从 64 涨到 256，同样的 $q, k$ 分布，饱和会更严重还是更轻？
继续回「继续」；没懂就回「卡在表格这一步」。
````

## 回合 8–9：3b 与第 4 节（格式相同，略）

3b 用"softmax 的偏导 $\partial a_i/\partial s_j = a_i(\delta_{ij}-a_j)$ 在 $a$ 接近 one-hot 时趋于 0"讲梯度为什么变小；第 4 节用 $\operatorname{Var}(s/\sqrt{d_k}) = d_k/d_k = 1$ 收口，并对比除以 $d_k$ 会把方差压到 $1/d_k$、输出过度平滑。两节各有自己的定位块、检查点与停点，结构与 3a 一致。

回合 10 用户回「懂了」，进入收束页。

## 回合 10：收束页

````markdown
## 串起来

| # | 结论 |
| --- | --- |
| 1 | 注意力输出是 value 的加权平均，权重来自分数 $s_i = q \cdot k_i$ |
| 2 | $s_i$ 的标准差是 $\sqrt{d_k}$，维度越高分数越大 |
| 3a | 分数大时 softmax 接近 one-hot |
| 3b | 接近 one-hot 时梯度变小，训练变慢、变不稳 |
| 4 | 除以 $\sqrt{d_k}$ 把方差拉回 1，softmax 不再饱和 |

一句话：缩放不是技巧，是把分数的量级拉回与维度无关的水平，使 softmax 工作在梯度正常的区间。

### 改进方向

**可行**
- 把固定的 $1/\sqrt{d_k}$ 换成可学习缩放 → 适配不同层的分数分布 → 代价：多一个参数、需要监控数值范围
- 在 Q、K 上各加一层归一化（QK-norm）→ 从源头压住分数尺度 → 代价：多两次归一化开销
- 低精度推理时对 logits 做区间裁剪 → 抑制极端分数导致的溢出 → 代价：引入一个阈值超参

**不可行**
- 去掉缩放、保留 softmax → 大 $d_k$ 下分数标准差 $\sqrt{d_k}$，softmax 接近 one-hot，训练不稳
- 改成除以 $d_k$ → 方差被压到 $1/d_k$，注意力接近均匀，等于放弃选择能力
- 训练时把 softmax 换成硬 one-hot → 不可导，梯度传不回去

自测（可选）：为什么除以 $d_k$ 不如除以 $\sqrt{d_k}$？写出两者的方差。
暂停区还有 P1（多头注意力），要现在展开吗？
````

## 反例对照：一口气全倒

同一个问题，错误做法是这样开头的：

> scaled dot-product attention 计算 $\operatorname{softmax}(QK^{\top}/\sqrt{d_k})V$。这里除以 $\sqrt{d_k}$ 是为了防止梯度消失，因为 $q \cdot k$ 的方差是 $d_k$，除以 $d_k$ 又会让方差过小，softmax 输出过于平滑，所以取 $\sqrt{d_k}$。另外多头注意力是……

失败点：

1. 没有骨架，读者不知道这几个结论之间是什么关系。
2. 四节内容压成一段，哪一步没懂无法定位。
3. 没有停顿，用户只能回"没看懂"或"哦"。
4. 收尾附带了跑题内容，主线被稀释。

对照本示例：同样的信息量，拆成 4 个可独立复述的结论，每一步都停一次，卡住时只换讲法不换话题。

## 附录：用户要例子时怎么给

算法类默认不给例子；下面演示用户提出后补充的形式。以玩具版 Diffie–Hellman 为例，实例只验证"双方各自算出的密钥相同"这一个结论，不引入新术语。

````markdown
**输入**：大素数 $p = 23$、生成元 $g = 5$，双方私钥 $a = 6$、$b = 15$（均为整数的私密取值）
**输出**：双方各自算出的共享值，应为同一个整数

**跑一遍**

1. Alice 算 $A = 5^{6} \bmod 23 = 8$
2. Bob 算 $B = 5^{15} \bmod 23 = 19$
3. Alice 收到 $B$，算 $B^{a} = 19^{6} \bmod 23 = 2$
4. Bob 收到 $A$，算 $A^{b} = 8^{15} \bmod 23 = 2$

对照本节结论：两边都得到 $2$，说明交换的是"能算出同一个数"的材料，而不是密钥本身；把 $a = 6$ 换成别的值，这个等式仍然成立。
````

写实例时守住三条：规模小到手算、每步给中间值、结尾扣回本节结论。反例是直接跑 2048 位参数——跟不下去，等于没讲。

# 极简外壳（三块拼装）

需要立刻开讲时，把下面三块按顺序拼起来即可。完整变体见 [../references/shell-templates.md](../references/shell-templates.md)。

## 块一：骨架页（第 1 回合，只发这块）

```markdown
## 总体路线

一句话：这次要弄懂〈总问题〉。

**依赖**：1 〈功能名〉 → 2 〈功能名〉 → 3 〈功能名〉

| # | 本节 | 你会得到的结论 | 为什么排在这 |
| --- | --- | --- | --- |
| 1 | 〈功能名〉 | 〈一句话结论〉 | 〈依赖关系〉 |
| 2 | 〈功能名〉 | 〈一句话结论〉 | 〈依赖关系〉 |
| 3 | 〈功能名〉 | 〈一句话结论〉 | 〈依赖关系〉 |

共 3 节，每节 300–600 字（复杂主题按区间，如 800–1200 字），第 k 节依赖第 k−1 节。

先不展开：加速与优化、采样与随机化、实现与调参——需要哪条说一声。

要改分节、合并或跳过，现在说；没问题回「开始」。
```

有分叉或汇合时，在"依赖"位置上一张 Mermaid `flowchart LR`，并紧跟一段缩进文本树做回退。

## 块二：单节（每回合只发一块）

```markdown
### 第 1 / 3 节 · 〈标题〉

`███░░░ 1/3`　`[1] → 2 → 3`

- 从哪来：这是起点，回答〈总问题〉的〈第一层〉。
- 为什么现在：不先定〈概念〉，后面〈机制〉无从谈起。
- 到哪去：本节结论会成为第 2 节的输入。

本节目标：读完能说出〈可检验的判断〉。

〈正文：结论先行 → 机制或例子 → 边界〉

算法类在这里放"跑一遍"：最小参数，3–7 步，每步给中间值，结尾扣回本节结论。

一句话回收：〈本节结论〉，所以第 2 节可以开始问〈下一个问题〉。

**停一下**：〈一个针对最可能误读的问题〉？
继续回「继续」；没懂就回「没懂 + 卡在哪」，我换一种讲法。
```

## 块三：收束页（全部讲完后）

```markdown
## 串起来

| # | 结论 |
| --- | --- |
| 1 | 〈结论〉 |
| 2 | 〈结论〉 |
| 3 | 〈结论〉 |

一句话：〈总答案〉。

### 改进方向（算法、协议、系统设计类必给）

**可行**：〈改动〉→ 解决〈…〉→ 代价〈…〉
**不可行**：〈改动〉→ 会破坏〈假设〉／触发〈攻击〉／代价涨〈…〉

你要先展开哪条？选中后我生成背景卡，复制到新会话继续分节讲。
```

## 四条自检

1. 本回合是不是只发了一块节？
2. 定位块有没有回答"从哪来、为什么现在、到哪去"，位置示意是否标出了当前节？
3. 检查点是不是只有一个问题，并且给了继续/没懂两条路？
4. 第一遍是否只讲框架，加速、采样、实现细节都进了待问清单？

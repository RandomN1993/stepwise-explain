# 逐节讲解（stepwise-explain）

> GitHub: <https://github.com/RandomN1993/stepwise-explain>　·　版本 v7.0.0（2026-11-14）

把需要多步理解的问题拆成若干节：先只给路线图，确认后一次只讲一节，每节开头说明它在整体框架中的位置，节末用一个可检验的问题停住，等你说懂了再讲下一节。

它不是"把长答案分段"——分段只是排版，本技能控制的是**节奏与停点**。

## 四条规则

1. **先骨架，后正文。** 第一回合只给路线图与每节结论，不给正文。
2. **一回合只讲一节。** 不自动续讲，不用定时器或计划任务代替你确认。
3. **每节先报位置。** 三行说清"从哪来、为什么现在、到哪去"，不是只写"第 2 节"。
4. **先简后全。** 每节先给一句正确但简洁的描述，再展开完整描述；讲清楚即可。

## 用法

在 DeepSeek Harness 里（技能已装在 `~/.dsh/skills`，所有项目可见）：

- **手动调用**：输入 `/stepwise-explain`，后面直接跟问题。
- **自动触发**：直接问一个需要多步理解的问题，模型从技能目录读到 description 后会自己加载；说"分节讲""一节一节讲""讲完一节等我懂了再讲下一节"也行。
- **设成默认**：见下面的「长期默认」。

只想手动调用、不让模型自动加载，在 `SKILL.md` frontmatter 加 `disable-model-invocation: true`；只想让模型用、不给人 `/` 调用，加 `user-invocable: false`。

典型一轮：

1. 我给路线图：一行依赖拓扑 + 每节一行的结论表，你说「开始」或改分节。
2. 我讲第 1 节，开头标出当前位置（`1 → [2] → 3`），先用一句话讲清、再展开完整描述，末尾问一个问题，停住。
3. 你说「继续」→ 下一节；说「没懂」→ 同一节换讲法或退回去补接口，不跳过。
4. 全讲完给收束页：每节一句结论 + 一句话总答案 + 改进方向（算法、协议、系统设计类）。

算法类讲解会先写清「输入：类型/尺寸/取值域」「输出：类型与含义」，再讲机制与边界。

第一遍只讲框架：加速与优化、采样与随机化、实现与调参默认跳过，在骨架页的"先不展开"里列出，你点名哪条再讲——不会悄悄漏掉，也不让你一上来就淹没在细节里。

涉及对比时一律并排多列（维度做行、对象做列），差异处标「▲」，不用"先说 A 再说 B"的两段式。

你提过的全部要求整理在 [REQUIREMENTS.md](https://github.com/RandomN1993/stepwise-explain/blob/main/REQUIREMENTS.md)，按提出顺序编号并标注落地位置。

收束页的改进方向分「可行」与「不可行」，不可行的要写清破坏哪个假设或触发哪种攻击。你选中哪条，才为它生成背景卡，复制到新会话继续按同一方式讲——新会话同样先给骨架页。

官方 DeepSeek 网页版与手机 App 不读本地技能目录，这个技能只在 DeepSeek Harness 里生效。

## 不适用

一句话能答完的事实、定义、是非判断；你只要产物（代码、命令、文件）不要讲解；你已经明确要求"一次给全"。这些情况直接回答，不拆节。

## 安装

```bash
git clone https://github.com/RandomN1993/stepwise-explain.git
cd stepwise-explain
ln -sfn "$PWD/skills/stepwise-explain" ~/.dsh/skills/stepwise-explain
ln -sfn "$PWD/skills/stepwise-explain" ~/.agents/skills/stepwise-explain
```

- `~/.dsh/skills/` 是 DeepSeek Harness 的用户级技能目录，所有会话可见。
- `~/.agents/skills/` 是跨 agent 的通用目录，Claude Code、Codex 等工具也读这里。

软链的好处是 `git pull` 后立即生效，不会留下两份副本。目标环境不支持软链时改用复制：

```bash
rsync -a --delete skills/stepwise-explain/ ~/.dsh/skills/stepwise-explain/
```

验证：`head -3 ~/.dsh/skills/stepwise-explain/SKILL.md` 能读到内容，且新会话里 `/stepwise-explain` 能被识别。

## 长期默认

如果希望"问多步问题就自动这样讲"，在你的用户级指令文件（本机是 `~/.dsh/AGENTS.md`）里加一行：

```markdown
- 多步问题默认用 /stepwise-explain 的方式讲解：先给路线图，一次一节，每节先报位置，讲完停住等确认；一句话能答完的问题直接答。
```

注意：默认全开会把简单问答也变成多轮，上面这行的后半句不能省。

## 与其他技能的分工

| 技能 | 管什么 | 何时用 |
| --- | --- | --- |
| stepwise-explain（本技能） | 过程：怎么讲、在哪停 | 还在理解阶段 |
| conversation-map | 事后：导图与讨论路径 | 讲完后想回忆整体结构 |
| conversation-book | 事后：成册文档 | 要把内容沉淀给别人看 |
| office 系列 | 产物转换 | 要 Word / PDF / PPT |

本技能不会自动调用它们；收束时最多提示一句。

## 已知边界

- 节奏依赖用户回合：一次只讲一节，意味着节多时轮次也多；嫌慢可以回「直接说结论」。
- "懂了"是主观信号，本技能无法验证你真正掌握；检查点只提供一个自测入口。
- 讲解不构成执行授权：讲到的命令、配置不会自动执行。
